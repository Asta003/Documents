## Сборка

### Vite падает с ошибкой парсинга project.yaml

**Признак.** Запуск `npm run dev` или `npm run build` завершается ошибкой в терминале:

```text
Error: YAMLParseError: unexpected token at line 3, column 5
at parseYaml (...)
```

Или:

```text
Error: project.yaml is missing required field: name
```

**Причина.** В `project.yaml` синтаксическая ошибка (лишний пробел, табуляция вместо пробелов, незакрытая кавычка) или пропущено обязательное поле. Vite-плагин читает все файлы `project.yaml` при сборке манифеста и не пропускает некорректные данные.

**Решение.** Проверьте файл в папке проблемного проекта:

1. Убедитесь, что все обязательные поля на месте: `name`, `summary`, `status`, `tags`. Поле `agents` необязательное, `entry` тоже.
2. Проверьте отступы: в YAML используются пробелы, не табуляция. Каждое поле — с новой строки, без лишних пробелов в начале.
3. Если в значении есть двоеточие или кавычки, заключите строку в кавычки: `summary: "Demo: first attempt"`.

Пример корректного файла:

```yaml
name: "My Demo"
summary: "A small experiment"
status: "experimental"
tags: ["demo", "test"]
```

**Проверка.** `npm run dev` запускается без ошибок, в терминале нет строк с `YAMLParseError` или `missing required field`.

Проверено запуском.


### Проект есть в папке, но его нет в манифесте

**Признак.** Вы создали папку в `projects/`, добавили `index.html` и `project.yaml`, но в боковом меню галереи проект не появился. Терминал при этом молчит, ошибок нет.

**Причина.** Vite-плагин собирает манифест только при старте или при изменении файлов, которые он отслеживает. Если вы создали папку, когда dev-сервер уже работал, плагин мог её не заметить. Вторая возможная причина: имя папки начинается с точки или содержит символы, которые плагин пропускает при сканировании.

**Решение.**

1. Перезапустите dev-сервер: остановите `Ctrl+C` и снова `npm run dev`.
2. Проверьте имя папки: латиница, без пробелов, без точки в начале. Например, `my-demo`, а не `.my-demo` и не `мой демо`.

**Проверка.** После перезапуска в терминале появляется строка о пересборке манифеста, а проект виден в боковом меню.

Проверено по коду.

## Галерея

### Проект появился в меню, но превью пустое

**Признак.** В боковом меню есть название проекта, вы кликаете по нему, но в основной области пусто: белый или прозрачный фон, никакого содержимого.

**Причина.** Загрузчик песочницы читает файл, указанный в поле `entry` (по умолчанию `index.html`), и вставляет его в Shadow DOM. Если файла нет по указанному пути или в нём нет видимого контента, превью остаётся пустым.

**Решение.**

1. Проверьте, что файл `index.html` (или тот, что указан в `entry`) лежит в папке проекта.
2. Откройте файл и убедитесь, что внутри `<body>` есть хоть какой-то видимый элемент: заголовок, параграф, кнопка. Пустой `<body></body>` даст пустое превью.
3. Если точка входа называется иначе (например, `main.html`), добавьте в `project.yaml` строку: `entry: "main.html"`.

**Проверка.** В превью виден текст или элемент из вашего `index.html`.

Проверено по коду.

### Стили проекта «протекли» в оболочку

**Признак.** После открытия вашего проекта фон галереи или цвет кнопок навигации изменился. Или стили оболочки перекрасили ваш проект.

**Причина.** Песочница использует Shadow DOM для изоляции, но изоляция работает только для стилей, которые находятся внутри файла проекта. Если вы подключили внешний CSS через `<link>` или использовали `document.body.style` в скрипте, это может выйти за пределы песочницы.

**Решение.**

1. Убедитесь, что все стили проекта находятся в `<style>` внутри `index.html` или в отдельном CSS-файле, подключённом через `<link>` внутри проекта. Shadow DOM изолирует их от оболочки.
2. Не используйте `document.body` или `document.documentElement` в скриптах проекта: внутри песочницы `document` относится к теневому корню, но обращение к `body` может не сработать так, как вы ожидаете. Работайте с элементами через `document.currentScript.getRootNode()`.

**Проверка.** После открытия проекта фон и стили галереи остаются прежними, а стили вашего проекта применяются только внутри превью.

Проверено по коду.

## Песочница

### Скрипт внутри песочницы не находит элемент

**Признак.** В консоли браузера ошибка:

```text
TypeError: Cannot read properties of null (reading 'addEventListener')
```

или

```text
Uncaught TypeError: document.getElementById(...) is null
```

**Причина.** Внутри Shadow DOM `document` указывает на глобальный документ страницы, а не на теневой корень. Элементы вашего проекта находятся в теневом дереве, и `document.getElementById` их не видит.

**Решение.** Получите корневой узел песочницы и ищите элементы внутри него:

```js
const root = document.currentScript.getRootNode();
const button = root.querySelector('#my-button');
button.addEventListener('click', () => { ... });
```

**Проверка.** Скрипт выполняется без ошибок в консоли, обработчик срабатывает при клике на элемент внутри превью.

Проверено по коду.

## Если ничего не помогло

Создайте issue в репозитории проекта и приложите:

- версию Node.js: вывод `node --version`;
- версию npm: вывод `npm --version`;
- операционную систему;
- команду, которую вы запускали (`npm run dev` или `npm run build`);
- полный текст ошибки из терминала, текстом, а не скриншотом;
- содержимое вашего `project.yaml`, если проблема связана с манифестом.
