## Структура проекта

Каждый проект — это папка внутри `projects/`. Обязательные файлы: `index.html` и `project.yaml`.

| Путь | Назначение |
|------|------------|
| `projects/<slug>/` | Папка проекта. Имя папки — это `slug`, используется в URL |
| `projects/<slug>/index.html` | Точка входа. Если файл называется иначе, нужно указать поле `entry` в `project.yaml` |
| `projects/<slug>/project.yaml` | Метаданные, которые оболочка собирает в манифест |
| `projects/<slug>/*` | Любые статические ресурсы (скрипты, стили, картинки) копируются в сборку как есть |

## Поля файла project.yaml

Файл лежит в корне каждой папки проекта. Все поля, кроме `agents` и `entry`, обязательны.

### name

Отображаемое название проекта в галерее и боковом меню.

| Поле | Значение |
|------|----------|
| Тип | Строка |
| По умолчанию | Не установлено |
| Обязательность | Обязательное |
| Пример | `name: "Particle Playground"` |

### summary

Краткое описание проекта, выводится под названием в каталоге.

| Поле | Значение |
|------|----------|
| Тип | Строка |
| По умолчанию | Не установлено |
| Обязательность | Обязательное |
| Пример | `summary: "Canvas-driven particle flow demo"` |

### status

Текущее состояние проекта. Определяет визуальную метку (бейдж) в каталоге.

| Поле | Значение |
|------|----------|
| Тип | Строка (перечисление) |
| Допустимые значения | `stable`, `experimental`, `wip` |
| По умолчанию | Не установлено |
| Обязательность | Обязательное |
| Пример | `status: "experimental"` |

### tags

Список тегов для поиска и фильтрации проектов в каталоге.

| Поле | Значение |
|------|----------|
| Тип | Массив строк |
| По умолчанию | Не установлено |
| Обязательность | Обязательное |
| Пример | `tags: ["canvas", "animation", "2d"]` |

### agents

Список AI-агентов или инструментов, использовавшихся при создании проекта.

| Поле | Значение |
|------|----------|
| Тип | Массив строк |
| По умолчанию | Не установлено |
| Обязательность | Необязательное (если не указано, иконки агентов не отображаются) |
| Пример | `agents: ["Claude", "ChatGPT"]` |

### entry

Имя файла точки входа в проект.

| Поле | Значение |
|------|----------|
| Тип | Строка |
| По умолчанию | `index.html` |
| Обязательность | Необязательное (если файл называется именно `index.html`) |
| Пример | `entry: "main.html"` |

## Скрипты npm

Общий вид вызова:

### dev

Запускает Vite в режиме разработки с горячей перезагрузкой.

| Поле | Значение |
|------|----------|
| Аргументы | Нет |
| Результат | Локальный URL (обычно `http://localhost:5173`) и запущенный сервер |
| Ошибки | Порт занят — Vite предложит следующий свободный порт |
| Пример | `npm run dev` |

### build

Собирает проект в папку `dist/`, пригодную для публикации.

| Поле | Значение |
|------|----------|
| Аргументы | Нет |
| Результат | Папка `dist/` с готовыми файлами и сгенерированным манифестом |
| Ошибки | Синтаксическая ошибка в `project.yaml` — сборка падает с сообщением от Vite |
| Пример | `npm run build` |

### preview

Запускает локальный сервер для просмотра собранной версии из `dist/`.

| Поле | Значение |
|------|----------|
| Аргументы | Нет |
| Результат | Локальный URL для проверки production-сборки |
| Ошибки | Папка `dist/` отсутствует — сначала нужен `build` |
| Пример | `npm run preview` |

## Процесс сборки

Кастомный Vite-плагин обходит папку `projects/`, читает каждый `project.yaml` и собирает общий манифест.

| Этап | Что происходит | Результат |
|------|----------------|-----------|
| 1. Сканирование | Плагин находит все папки в `projects/` | Список путей к проектам |
| 2. Чтение метаданных | Из каждой папки читается `project.yaml` | Объекты с полями `name`, `summary`, `status`, `tags`, `agents`, `entry` |
| 3. Валидация | Проверяется наличие обязательных полей | Ошибка сборки, если поле отсутствует |
| 4. Генерация манифеста | Все объекты объединяются в массив | Файл `/projects/manifest.json` |
| 5. Копирование ресурсов | Содержимое `projects/<slug>/` копируется в `dist/projects/<slug>/` | Статические файлы доступны в production |

## Коды завершения

| Код | Значение |
|-----|----------|
| `0` | Скрипт выполнен успешно |
| `1` | Ошибка сборки, валидации или запуска |

> Код завершения для случая, когда папка `projects/` пуста, не установлен:
> в исходном коде такая ситуация отдельно не обрабатывается.
